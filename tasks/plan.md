# 实施计划：画布、网络、OSS 与 API 性能可靠性治理

## 概览

基于现有实现和测试，定位画布交互/渲染、前端网络与本地媒体缓存、OSS 资源访问，以及前后端 API 契约中的可复现缺陷。优先采用最小增量修复，保持现有技术栈、接口语义和用户数据隔离；没有基准证据的微优化不作为交付内容。

## 当前约束

- 工作区已存在大量未提交改动，不能回滚或覆盖；本次只追加必要修改。
- 前端公共 API 客户端是 `web/src/services/api/request.ts` 导出的 `apiClient` / `request`。
- 后端遵循 `handler -> service -> repository` 分层，资源读取和删除必须经过归属校验。
- 远程资源以资源 ID/存储 key 作为稳定标识，浏览器缓存必须带用户 scope。

## 依赖关系

1. 先完成基线和代码地图。
2. 先修复公共网络/缓存与 API 契约，再处理依赖这些契约的页面和画布调用方。
3. 画布高频渲染修复必须与节点/资源生命周期验证一起完成。
4. 所有代码改动完成后执行聚焦测试、前端类型检查/构建和后端测试。

### 拆包验证记录

- 第一轮组件拆分时，大于 500 KB 的 JS chunk 仍为 10 个，但 `canvas-node` 从约 390.17 KB 降至约 358.11 KB，图表依赖独立为约 23.29 KB 的 `chart-node`，提示词编辑器保持约 389.67 KB 的独立异步包。
- 受限 Shiki 插件仅按需加载 Bash、CSS、Go、HTML、Java、JavaScript、JSON、Markdown、Python、Rust、SQL 和 TypeScript；C/C++ 与未知语言保留纯文本代码块，不加载语法模块。
- 最终干净目录构建中，大于 500 KB 的 JS chunk 从 10 个降至 7 个；未生成 C、C++、Emacs Lisp 或 Shiki WASM 语言资产。常用语言最大单包为 TypeScript 约 176.83 KB，均低于告警阈值。
- 剩余 7 个大异步包约为 1,778.37 KB、1,381.17 KB、1,348.71 KB、708.68 KB、647.15 KB、535.61 KB 和 520.34 KB，来源仍为独立运行时/功能边界（WASM/LSP 运行时、tldraw、项目页、Three.js 等），不通过提高阈值或无差别切块掩盖。
- Rolldown `maxSize: 450 KB` 实验将部分依赖切成大量入口组合命名的 vendor chunk，但仍产生约 1.82 MB、780 KB、663 KB 和 622 KB 的大 chunk，且增加碎片化，故不保留。
- 最终验证：受限高亮聚焦测试 3/3、前端全量测试 1417/1417、TypeScript 类型检查、Vite 生产构建、后端 `go test ./...` 和 `git diff --check` 全部通过。

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 现有未提交改动与本次目标重叠 | 高 | 修改前读取当前内容，按函数/调用链增量编辑，不回滚用户改动 |
| 画布高频事件改变交互语义 | 高 | 先运行现有画布测试，再补充针对取消、缩放、拖拽和卸载的测试 |
| 缓存优化造成跨账号数据泄漏或旧资源 | 高 | 所有 cache key 保持用户 scope，切换账号时使进行中任务失效 |
| OSS provider 行为差异 | 中 | 复用已有 provider 抽象，测试公开 URL、代理回退、Range 和失败清理 |
| 本地环境缺少后端依赖/服务 | 中 | 先执行可运行的单元与静态验证，无法运行的集成路径如实记录 |
